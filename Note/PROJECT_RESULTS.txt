1) TỔNG QUAN SẢN PHẨM
─────────────────────────────────────────────────────────────────────────────

Dự án Chatbot-RAG (Chatbot Pháp Luật Việt Nam) là một hệ thống trí tuệ nhân tạo 
kết hợp Retrieval-Augmented Generation (RAG) để trả lời câu hỏi về pháp luật 
Việt Nam với độ chính xác cao.

THÀNH PHẦN CHÍNH:

┌─ 1️⃣ HỆ THỐNG XỨJLÍ DỮ LIỆU (Data Processing Pipeline)
│   - Làm sạch, chuẩn hóa, chia chunks từ dữ liệu pháp luật gốc
│   - Input: 500MB - 1GB dữ liệu HTML/TXT
│   - Output: chunks.json (khả tìm kiếm), metadata.json
│
├─ 2️⃣ HỆ THỐNG EMBEDDING (Embedding Generation)
│   - Chuyển text chunks thành dense vectors
│   - Model: sentence-transformers (384-dim)
│   - Output: embeddings.npy (vector database)
│
├─ 3️⃣ HỆ THỐNG TÌM KIẾM (Vector Search - FAISS)
│   - Index xây dựng từ embeddings
│   - Tìm top-k chunks liên quan (similarity search)
│   - Type: IndexFlatL2 (100% accuracy)
│
├─ 4️⃣ HỆ THỐNG SINH NỘI DUNG (RAG + LLM Generation)
│   - Orchestrator: RAGSystem (search + prompt engineering + generation)
│   - LLM: Google Gemini (hoặc OpenAI/Claude adapter)
│   - Retry logic: Multi-level fallback mechanism
│   - Output: Answer + sources (cited with specific articles)
│
└─ 5️⃣ GIAO DIỆN NGƯỜI DÙNG (Frontend + API)
    - FastAPI Backend: REST endpoints (/chat, /search, /health)
    - Streamlit Frontend: Web UI với interactive controls
    - Deployment: Containerized (Docker-ready)

─────────────────────────────────────────────────────────────────────────────

  ├─ Dung lượng: 354 MB
  ├─ File: faiss_index.bin
  ├─ Type: IndexFlatL2 (brute-force L2 distance)
  ├─ Vectors: ~100,000 (384-dim)
  ├─ Configuration:
  │  ├─ Index type: flat (100% accuracy, no approximation)
  │  ├─ Search latency: ~100ms per query (CPU)
  │  ├─ Load time: ~5-10 seconds at startup
  │  └─ Memory (in-RAM): ~400 MB during runtime
  │
  ├─ Companion file: faiss_index_info.json
  │  └─ Metadata: num_vectors, dimension, index_type, timestamp
  │
  └─ Dùng để: Fast similarity search (nearest neighbor lookup)

4) TÍNH NĂNG & KHẢ NĂNG
═══════════════════════════════════════════════════════════════════════════════

4.1) Retrieval (Tìm kiếm)
─────────────────────────────────────────────────────────────────────────────

✓ Similarity search:
  - FAISS IndexFlatL2: 100% accuracy
  - Configurable top_k (default 3, max 5)
  - Return format: [chunk_id, content, similarity_score, metadata]

✓ Multilingual support:
  - Model: sentence-transformers (multilingual)
  - Languages: Vietnamese, English, etc.
  - Encoding: UTF-8

✓ Metadata filtering (future):
  - Filter by document type (Luật, Nghị định, etc.)
  - Filter by date range
  - Filter by scope (relevant departments)


4.2) Generation (Sinh nội dung)
─────────────────────────────────────────────────────────────────────────────

✓ Multi-LLM support:
  - Google Gemini (primary)
  - OpenAI (fallback)
  - Anthropic Claude (fallback)
  - Local LLM via Ollama (optional)

✓ Prompt engineering:
  - Role-based prompts (legal assistant)
  - Anti-hallucination rules
  - Citation requirement
  - Context formatting (numbered chunks)

✓ Multi-level retry logic:
  - Attempt 1: Original (top_k=3, max_tokens=1500, temp=0.7)
  - Attempt 2: Reduced top_k=3, chunks truncated, temp=0.49
  - Attempt 3: Further reduced, temp=0.34
  - Fallback: Return chunks + error message (graceful degradation)

✓ Safety & robustness:
  - Guarded LLM access (no unsafe quick-accessors)
  - Safe candidate parsing
  - Token budget calculation
  - MAX_TOKENS error handling


4.3) API & Integration
─────────────────────────────────────────────────────────────────────────────

✓ FastAPI Backend:
  - POST /chat
    ├─ Input: {query, top_k, temperature, max_tokens}
    └─ Output: {answer, sources: [{dieu, chuong, content_preview, ...}], debug}
  
  - POST /search
    ├─ Input: {query, top_k}
    └─ Output: {results: [{chunk, score, metadata}]}
  
  - GET /health
    ├─ Status: RAG system ready?
    └─ Info: model info, num chunks, index type

✓ Streamlit Frontend:
  - Chat tab: Interactive Q&A with sources
  - Search tab: Raw retrieval results
  - Settings: top_k, temperature, max_tokens sliders
  - UI language: Vietnamese

✓ Testing:
  - Unit tests: search accuracy, prompt formatting
  - Integration tests: end-to-end chat
  - Manual QA: legal correctness verification


4.4) Deployment & Operations
─────────────────────────────────────────────────────────────────────────────

✓ Containerization:
  - Dockerfile (planned): multi-stage build
  - docker-compose.yml: FastAPI + Streamlit services
  - Volume mounts for FAISS index, chunks, embeddings

✓ Configuration:
  - .env file: API keys, model selection, paths
  - CLI args: top_k defaults, temperature, index type
  - Runtime parameters: nprobe, batch size

✓ Observability:
  - Health check endpoint
  - JSONL logging (LLM calls, retry attempts)
  - Error tracking + fallback logging
  - Optional Prometheus metrics (future)

✓ Scalability:
  - Batch processing for embeddings
  - Index switching (IndexFlat → IVF → HNSW as dataset grows)
  - Modular architecture (swap components)
